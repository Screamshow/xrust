# Подготовка MIPS OpenWrt, 29 октября 2026

Кандидат Xrust 0.0.29 в существующей ветке dev. Публикация и перенос в main
ожидают обсуждения описаний выпусков с владельцем. Публичный тег не создавался.

## Архитектура и сборка

Для MT7628AN / ramips/mt76x8 добавлена `mipsel_24kc`: ELF32 little-endian,
MIPS32r2 O32, soft-float, без требования FPU или 64-битных атомарных инструкций.
Оставшиеся AtomicU64 в runtime и дополнительном allocstat используют имеющийся
portable-atomic. ARM64 и x86_64 сохраняют прежние целевые архитектуры.

Rust `mipsel-unknown-linux-musl` — Tier 3 без готовой стандартной библиотеки.
`scripts/build_mips_openwrt.sh` собирает std из rust-src, соответствующего rustc,
с `-Z build-std=std,panic_abort`. RUSTC_BOOTSTRAP включается только в этом скрипте.
Локально использован Rust 1.99.0; CI устанавливает stable и его rust-src вместе.

`scripts/openwrt_mips_toolchain.sh` загружает официальный OpenWrt 24.10.4
ramips/mt76x8 GCC 13.3.0 musl toolchain, проверяя SHA-256
`2ede1fb29175bf7b8888606017dd71123e8e85679956ef708e626d1b60fa3065`.
Это инструмент сборки, не источник пакетов для установки на роутер.

Бинарник динамически использует `/lib/ld-musl-mipsel-sf.so.1`, libc и libgcc
прошивки. Зависимости MIPS-пакетов: ca-bundle, kmod-tun, libc, libgcc.
Системные зависимости устанавливает пакетный менеджер из репозиториев
конкретной прошивки. Пакеты ARM/MediaTek filogic для этого не используются.
Размер проверенного бинарника — 9 705 532 байта. Свободная flash должна вмещать
также Forkop, зависимости, рабочие файлы и подготовленный пакет отката.
Поддержка архитектуры не означает пригодность любой платы с этим SoC.

## Проверки

- Собраны release-бинарники MIPS, ARM64 и x86_64. Native x86_64 regression
  `xhttp_h2_keepalive`: 6 тестов успешно.
- `qemu-mipsel -cpu 24Kc` запускает реальный MIPS ELF и сообщает xrust 0.0.29.
  Это user-mode эмуляция процесса; новая виртуальная машина не создавалась.
- `scripts/test_mips_runtime.py`: конфиг принят, HTTP и SOCKS5 передали по
  262144 байта с проверкой SHA-256 через TLS-прокси. XRUST_AF_ALG=off исключает
  криптоускорение хоста; согласован TLS_AES_256_GCM_SHA384. Проверены UDP DNS
  hijack и Clash API. Сертификат и серверы — одноразовые loopback fixtures.
- На CPU 24Kc выполнены core-crypto tests: 30 успешно, 4 ignored; doc-test
  дополнительно ignored. Для std/test с panic=abort использованы отдельный
  CARGO_TARGET_DIR, `-Z build-std=std,test,panic_abort -Z panic-abort-tests` и
  `--test-threads=1 -Z unstable-options --force-run-in-process`.
- `scripts/test_mips_package_elf.py` проверяет отбрасывание hard-float,
  неподходящей ISA, endian/class и повреждённого ELF до упаковки.
- Настоящие OpenWrt host opkg и apk установили MIPS-пакеты в отдельные
  временные корни, обновили тестовую ревизию 1 → 2, вернули 2 → 1 и удалили
  пакет. Изменённый `/etc/config/sing-box` сохранён на каждом шаге; после
  отката совпал хеш бинарника. Ревизия 2 — только локальный fixture, не релиз.
  Проверены отказы при big-endian mips_24kc и отсутствии libgcc.
  Зависимости представлены пустыми metadata fixtures, service hooks отключены;
  эти тесты не доказывают lifecycle на настоящем MIPS-роутере.
- Forkop installer core plan и выбор версий выполнены локальным ucode:
  точное совпадение mipsel_24kc для APK/IPK; чужой ARM64 не принимается;
  старые релизы без MIPS не показываются как доступный откат.
- Release finalizer и mirror publisher принимают полный набор из 10 пакетов
  для пяти архитектур, требуют пары APK/IPK, сохраняют исторические наборы.

## Границы проверки

HILINK HLK-7628N и Rockchip отсутствуют в доступе. Не измерены потребление RAM,
скорость, flash конкретного устройства, TUN/nftables и реальный пользовательский
трафик на этих платах. Нельзя утверждать пригодность платы с 8 МиБ flash.
Скриншот не содержит объём RAM/flash.

Обе существующие VMware VM были недоступны по SSH при дополнительных MIPS
проверках. Выполнены локальные изолированные проверки; основной GL-MT6000
не изменялся. Ранее проверенный полный цикл Forkop на x86 VMware описан в
Forkop `docs/dev-260-preparation-2026-10-29.md`; это не аппаратный тест MIPS.

До 0.0.29 опубликованных MIPS-пакетов нет: первый переход с другого ядра
может откатиться к прежнему ядру только при наличии его точного совместимого
пакета. Выбрать старый ARM64/x86 пакет вместо отсутствующего MIPS нельзя.
Полный lifecycle установки/автоотката на MIPS требует доступного устройства.
